# herdr 0.9.5 호환 통합 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. (No subagent tool is
> available in this harness; native execution is the only route.)

**Goal:** PR #4(herdr 0.9.5 호환)를 `main`에 반영하고, PR #3의 검증된 설계 문서
(`DESIGN.md`/`CLAUDE.md`)를 0.9.5·#4 레이아웃에 맞게 이식해 하나의 리뷰 가능한 결과로 만든다.

**Architecture:** #4의 코드·테스트를 그대로 베이스로 삼는다(**`src/` 무변경**). 추가 작업은
문서 이식뿐이다. `src/`가 바뀌지 않으므로 `dist/`는 #4가 이미 재빌드한 상태를 유지하며,
재현성만 확인한다. 검토 결과에 따라 `herdr_handoff` 기본값은 #4의 `visible`을 유지한다.

**Tech Stack:** TypeScript(strict), Node 18+, MCP(stdio), `node:test`, `tsx`.

**Spec:** `docs/superpowers/specs/2026-11-18-herdr-0.9.5-integration-design.md`

## Global Constraints

- 기준 CLI는 **herdr 0.9.5**.
- `dist/`는 커밋된다 — `src/`를 바꾸면 반드시 `npm run build`; 이 계획은 `src/`를 바꾸지 않는다.
- `npx tsc --noEmit` 통과, `npm test` **56개 전부 통과**.
- `herdr_handoff` 기본 읽기 소스는 `visible` 유지(코드 변경 없음).
- 커밋 메시지: lowercase conventional(`fix:`/`feat:`/`docs:`/`chore:`), 이모지 없음, `refs #N`.
- 기여자 이력 보존: #4 커밋은 그대로 fast-forward로 가져온다.

## Review Focus

- **문서가 0.9.5 실제 동작과 어긋나지 않는가** — 특히 usage 문자열 예시. `pane run`은 0.9.5
  `herdr pane`에 나열되므로 "미표기" 예시로 쓸 수 없다.
- **이식 문서가 #4 레이아웃과 맞는가** — #4에는 `src/tools/resolve.ts`가 없다.
- **과장 없는 출처 표기** — 이식 문서의 주장 중 우리가 0.9.5에서 검증한 것과 원저자가 0.9.0
  라이브 세션에서 측정한 것을 구분한다.
- **`docs/superpowers/` 산출물의 취급** — #4 저자도 내부 계획 노트를 PR에서 제거했다. 이
  커밋은 PR에서 분리 가능해야 한다.

### Task 2: `DESIGN.md` 이식 (0.9.5/#4 기준으로 정정)

**Files:**
- Create: `DESIGN.md` (원본: `git show pr-3:DESIGN.md`)

**Interfaces:**
- Consumes: Task 1의 브랜치.
- Produces: `DESIGN.md` — 큐레이션 표면의 근거와 검증된 herdr 동작을 기록. `CLAUDE.md`가 링크.

- [ ] **Step 1: 원본을 그대로 가져오기**

Run: `git show pr-3:DESIGN.md > DESIGN.md`
Expected: 파일 생성.

- [ ] **Step 2: 출처 표기 정정**

`DESIGN.md`에서 다음 문장을:
```
Checked against herdr 0.9.0 and a live multi-agent session. Recorded here because
each one cost something to learn.
```
다음으로 교체:
```
Checked against herdr 0.9.5 for the CLI surface, and — by the original author —
against a live multi-agent session on herdr 0.9.0. Recorded here because each one
cost something to learn.
```

- [ ] **Step 3: 거짓이 된 `pane run` 예시를 실제 관측으로 교체**

`DESIGN.md`의 "The CLI help text is incomplete" 절에서 첫 두 문장:
```
`herdr --help` and the per-group summaries omit real commands: `pane run` exists
but is absent from `herdr pane` output. Confirm a command by running it with no
arguments — a usage line means it exists, falling back to the group listing means
it does not.
```
을 다음으로 교체:
```
`herdr`'s usage strings disagree with each other. In 0.9.5 the `herdr agent` group
lists `agent read ... --source ...|detection` while the bare `herdr agent read`
usage omits it; `herdr pane` does the opposite for `pane read`. Both subcommands
accept `detection` (probing `--source bogus` fails with `invalid read source`, so
the source is validated before the server is reached). Confirm a command by running
it with no arguments — a usage line means it exists, falling back to the group
listing means it does not.
```

- [ ] **Step 4: 문서 검증**

Run:
```bash
grep -n "pane run" DESIGN.md          # "미표기"라는 주장이 남아 있으면 안 됨
grep -n "0.9.5" DESIGN.md             # 출처 표기 포함
grep -n "detection" DESIGN.md          # detection 근거 유지
```
Expected: `pane run`은 "존재하나 미표기" 서술 없이 남지 않고, `0.9.5`/`detection` 문구 존재.

- [ ] **Step 5: 커밋**

Run:
```bash

```
Expected: 새 커밋 1개.

Expected: 파일 생성.

- [ ] **Step 2: `pane run` 예시를 실제 관측으로 교체**

"Verify against the running daemon, never the help text" 절의 첫 불릿:
```
- `herdr --help` and the group summaries are **incomplete**: `pane run` exists but
  is unlisted. Confirm a command by running it with no arguments — a usage line
  means it exists, falling back to the group listing means it does not.
```
을 다음으로 교체:
```
- Usage strings **disagree with each other**. In 0.9.5 `herdr agent` lists
  `agent read --source ...|detection` but bare `herdr agent read` omits it, while
  `herdr pane` and `herdr pane read` do the opposite for `pane read`. Confirm a
  command by running it with no arguments — a usage line means it exists, falling
  back to the group listing means it does not.
```

- [ ] **Step 3: 없는 파일 참조 제거 (#4에는 `resolve.ts`가 없음)**

Architecture 목록의:
```
- `src/tools/resolve.ts` — target → pane id. Resolve immediately before use; a pane
  moved across workspaces gets a **new** id, so never cache one.
```
을 다음으로 교체:
```
- `src/tools/types.ts` also holds target → pane resolution (`resolvePaneId`,
  `extractPaneId`). Resolve immediately before use; a pane moved across workspaces
  gets a **new** id, so never cache one.
```
