# herdr 0.9.5 호환 + 설계 문서 통합 (PR #3·#4 비교 반영) — 설계

날짜: 2026-11-18
상태: 승인 대기

## 의도 (why)

`herdr-mesh` 0.1.0은 현재 herdr CLI(0.9.x)와 명령이 어긋나 핵심 툴
`herdr_relay`, `herdr_handoff`, `herdr_agent_send`, `herdr_agent_wait`가 모두 실패한다
(이슈 #1). 커뮤니티가 같은 문제를 고치는 PR #3(StGerman)과 PR #4(wquesadac)을 냈고,
둘 다 열려 있으며 유지보수자 응답이 없다.

이 작업은 두 PR을 비교해 더 나은 것을 기반으로 삼고, 다른 쪽의 고유 자산을 이식해
**하나의 결과물**로 반영한다.

## 목표

- herdr 0.9.5에서 모든 툴이 동작한다.
- 회귀를 막는 단위 테스트(정확한 argv 검증)와 라이브 smoke 스크립트를 확보한다.
- 프로젝트가 왜 이렇게 생겼는지에 대한 **검증된 설계 문서**를 확보한다.
- `dist/`를 재빌드한다(이 저장소는 빌드 없이 GitHub 설치가 되도록 `dist/`를 커밋함).

## 비목표

- 소켓 transport, `herdr_fleet`, `herdr_await`, `herdr_transcript`, worktree fan-out
  (이슈 #2의 제안) — 이번 범위가 아니다.
- herdr API 1:1 미러링으로의 툴 표면 확장 — 하지 않는다(큐레이션 유지).

## 제약

- `dist/` 커밋 관례 유지 → `src/`를 바꾸면 반드시 재빌드.
- Node 18+, MCP stdio, 기존 `ToolDef` 구조(`buildArgs` 또는 `run`)를 따른다.

## 접근안

- **A. #4만 반영** — 가장 빠름. 0.9.5 대응·테스트 완비. #3의 설계 문서는 상실.
- **B. #4 기반 + #3 고유분 이식 (채택)** — 검증된 코드/테스트를 쓰고 문서 자산을 보존.
- **C. #3만 반영** — 더 작고 리뷰하기 쉽지만 테스트·0.9.5·키 정규화·타임아웃 전파가 없다.

B를 고른 이유: #4만이 자동 테스트(`npm test` 56개)와 0.9.5 CLI 대응을 갖췄고, #3의
설계 문서는 순수 추가라 얹기 쉽다.

## 결정 사항

- **베이스**: PR #4 (herdr 0.9.5, `v0.2.0`, 단위 테스트 56개, `scripts/smoke.mjs`).
  기여자 이력을 보존한다.
- **이식**: #3의 `DESIGN.md`와 `CLAUDE.md`. 단, #3은 `src/tools/resolve.ts`를 전제하므로
  #4 레이아웃(`resolvePaneId`/`extractPaneId`가 `types.ts`에 있음)에 맞게 수정한다.
  "0.9.0 검증" 표기는 0.9.5 기준으로 고친다. *(내 호출)*
- **`herdr_handoff` 읽기 기본값**: **#4의 `visible`을 유지한다.** #4가 라이브로 검증한
  선택이고(커밋 `1f73b9e`), `detection`은 응답 *본문* 읽기 품질이 검증되지 않았다. 다만
  `detection`을 포함한 모든 소스는 `read_source`로 선택 가능하다(이미 #4에 있음). *(검토 결과 반영)*
- **`herdr_agent_start`**: #4의 자동 생성 방식을 유지한다. `pane_id`/`split`/`split_from`
  를 모두 지원하고, 실패 시 생성물을 정리한다. *(내 호출)*
- **`herdr_agent_wait` 기본값**: #4의 "herdr 기본(idle, done, blocked)"을 유지한다(#3의
  idle+done보다 상위 호환). 레거시 `status` 별칭도 유지.
- **버전**: `0.2.0` 유지. 문서 포트는 `CHANGELOG.md`에 항목을 추가한다.

## 검토 결과 (완료, 2026-11-18)

herdr 0.9.5 클라이언트로 직접 프로빙하고, `pr-4`/`pr-3`를 worktree에서 빌드·테스트했다.

**검증됨**
- `pr-4`: `npx tsc --noEmit` 통과, `npm test` **56/56 통과**. `pr-3`: tsc 통과(테스트 없음).
- `#4`가 생성하는 argv는 herdr 0.9.5가 실제로 받는 명령/플래그와 일치한다
  (`agent prompt|wait --until|send-keys|start --kind --pane`, `pane send-text|wait-output|split`,
  `pane/agent read --source ...|detection`).
- `#4`의 `AGENT_KINDS` 24종이 herdr의 kind 목록과 정확히 일치하고, 잘못된 kind는
  클라이언트가 거부한다(`unsupported interactive agent kind`).
- `readSourceSchema`에 `detection` 포함은 **정당하다**: `agent read`·`pane read` 둘 다
  `--source detection`을 받는다(`--source bogus`는 `invalid read source`로 거부 → 검증됨).
  오히려 #3이 pane에서 detection을 뺀 쪽이 보수적 누락이다.
- 사용법 문자열의 불일치를 재확인: `herdr agent` 그룹은 agent read에 detection을 나열하지만
  무인자 사용법은 누락하고, `pane read`는 그 반대다.

**검토 소견 / 반영 시 수정 필요**
1. **`detection` 기본값(이식)은 미검증 결정** — 유효한 소스이긴 하나, 응답 *본문* 읽기에
   적합한지는 #4가 라이브로 검증하지 않았다(라이브로 검증한 건 `visible`, `recent`가 TUI
   패딩으로 비는 문제). #4의 `visible`을 뒤집는 변경이므로, 라이브 확인 전에는 `visible`
   유지 + `read_source` 옵션 노출이 안전하다. → **사용자 결정 필요.**
2. **`DESIGN.md`의 특정 예시가 0.9.5에서 거짓** — "`pane run`이 `herdr pane` 출력에 없다"고
   썼지만, 0.9.5 `herdr pane`에는 `herdr pane run <pane_id> <command>`가 **나열된다**.
   이식 시 예시를 수정해야 한다(뒤의 일반론—사용법 문자열 불일치—은 우리 프로빙으로 확인됨).
3. **`CLAUDE.md`가 존재하지 않는 파일을 가리킴** — `src/tools/resolve.ts`를 설명하지만
   #4에는 없다(resolve는 `types.ts`). 이식 시 구조 설명을 #4 레이아웃으로 수정.
4. **사소한 누락**: `herdr pane read`는 `--raw`를 지원하나 #4의 `herdr_pane_read`가
   노출하지 않는다(`herdr_wait_output`은 노출). 선택적 보강.

**미검증/한계**
- `normalizeKey`가 필요한 이유(`ctrl-c`→`ctrl+c`)는 서버 측 키 검증이라 라이브로만 확인된다.
  단위 테스트는 변환 로직만 증명한다.
- `extractPaneId`(#4, 문서화된 결과 형태 기반) vs `findPaneId`(#3, 재귀 탐색) 중 실제
  herdr 응답 형태와 더 맞는지는 서버가 필요하다. #4의 테스트는 문서화된 형태를 커버한다.
- **라이브 smoke 실행 불가**: herdr는 TTY가 필요하고 헤드리스 `server start`가 없다
  (`herdr` 실행 시 `cannot attach without a usable terminal`). `scripts/smoke.mjs`는
  이 환경에서 미실행 상태다. 사용자가 터미널에서 herdr를 띄우면 실행 가능.

치명적 정확성 버그는 발견되지 않았다.

## 남은 것 (빌더에게)

- `DESIGN.md`를 이식하되 버전 표기를 0.9.5로 고치고, `pane run` 예시(0.9.5에서 거짓)를
  실제 관찰된 예시(도움말 문자열 불일치: agent/pane read의 detection 표기)로 교체한다.
- `CLAUDE.md`를 이식하되 파일 구조 설명에서 `src/tools/resolve.ts`를 제거하고 `types.ts`
  기준으로 쓴다.
- handoff 기본값은 바뀌지 않으므로 코드 변경 없음(`read_source`는 이미 존재).
- `npm run build` + `npm test` 통과, `dist/` 재빌드. (문서만 바뀌어도 dist는 그대로 두되,
  빌드 재현성을 확인한다.)

## 랜딩 방식 *(내 호출)*

`integration/herdr-0.9.5-compat` 브랜치에서 #4 이력을 가져오고(기여자 보존), 후속
커밋으로 문서·기본값·재빌드된 `dist/`를 얹는다. 검증 후 PR로 제출하고, 승인되면 `main`에
머지한다. PR #3은 이 PR이 대체함을 근거와 함께 남기고 클로즈한다.
